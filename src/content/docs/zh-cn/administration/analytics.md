管理员的**运维监控**页面展示当前实例的运行观察。它适合调查容量与执行用量，但不能替代对员工工作成果的实际验收。

## 选择监控视图

| 视图       | 可查看内容                                                       |
| ---------- | ---------------------------------------------------------------- |
| 机器与容器 | 资源水位与历史趋势、容器筛选，以及可取得的进程信息。             |
| 项目运行   | 请求量、HTTP 并发、耗时、错误率、接口明细和数据库统计。          |
| Token 用量 | 已记录的会话结果用量，以及按模板、空间、员工或会话的趋势和分布。 |

资源与项目运行视图提供时间窗口选择，并可每 15 秒刷新。Token 数据手动刷新。解释图表前，先检查采集状态与采样时间。采集器不可用代表证据缺失，不能理解为负载为零。

## 调查接口问题

选择故障发生的时间范围，检查请求量、平均与 P95 耗时，以及错误率。按路由或关键词缩小接口表范围，将受影响接口与整体服务表现对照。

数据库面板既有当前连接和锁等待，也有累计事务、死锁等统计。累计数据库指标从最近一次统计重置开始，不能直接与短时间 HTTP 窗口比较。

## 正确阅读 Token 用量

选择开始时间、不包含在范围内的结束时间、时区、分组粒度，以及可选的模板、空间和员工筛选。用量以结果消息产生时间计入。

比较总量前，先检查**有用量记录 / 结果消息**。页面只读取已有用量字段，不估算缺失记录。缓存读取和创建单独列出，中间事件不会再次累加。删除会话后仍保留的证据可以参与统计，已经清理的证据无法计入。

页面以百万 Token 为单位，保留两位小数。较小的已知值可能四舍五入为 `0.00 M`；缺失值显示 `—`。分布只展示前 100 组时，总量和趋势仍包含全部匹配结果。

## 从观察到行动

记录筛选条件、采集时间、相关会话或接口，以及证据覆盖率。只有在相同范围内比较相近任务，才适合判断变化原因。Token 总量既不能衡量任务质量，也不能直接认定供应商账单金额。
