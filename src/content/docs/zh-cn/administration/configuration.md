配置分布在不同范围。遇到能力不可用时，应修改真正控制该能力的设置，避免在无关页面之间复制凭据或模型参数。

## 找到正确范围

| 范围         | 典型职责                                               |
| ------------ | ------------------------------------------------------ |
| 个人设置     | 个人偏好、账号连接、平台 Token、运行时配置与设备连接。 |
| 工作空间设置 | 共享空间信息、成员授权与空间凭据。                     |
| 员工与会话   | 执行员工、可用模型与思考等级、会话权限和执行目标。     |
| 管理后台     | 已发布模板、初始化配置、模型渠道与运维监控。           |

操作是否显示和成功，取决于账号与空间角色。无法访问设置时，请对应负责人在必要范围内调整。

## 配置模型渠道

管理员进入**运行时内核**，选择相关内核。界面分别提供 Claude Code 和 Pydantic AI 配置入口；在对应入口配置服务地址、凭据和模型标识符。可用协议与选项取决于内核和渠道用途。

Pydantic AI 将语言、决策与语音渠道分开配置。保存语音渠道，不代表主 Agent 自动获得可用语音入口。决策路由有独立配置与校验，也不同于选择对话模型。

保存后，检查目标模型是否出现在适用员工或会话中。先用短任务验证连通性，再调整多个员工。渠道保存成功不等于服务端点可访问。

## 配置凭据与设备

通过凭据字段保存或替换密钥。已有掩码值时，应区分保留原值、明确替换与主动清空。不要把密钥写进服务 URL、员工指令、空间记忆或故障截图。

在**设备连接**中，先检查设备的真实工作目录、能力和在线状态，再选择执行设备。默认设备可以处于离线状态，但此时无法执行工作。撤销设备授权影响后续访问，不会还原已经修改的文件。

## 验证与恢复

一次修改一项配置，保存后重复最小相关任务。分别检查员工初始化、模型可用性和连接授权。模型标记为当前不可用时，请管理员检查渠道，不要随意填写模型名称。

在变更记录中保留之前的非敏感配置和实际错误。先解决具体故障，再发布依赖该能力的自动化。
