## 贯穿案例

一个表单在必填项为空时显示了错误的提示。此次修改有两项检查：空值显示约定的提示，有效值仍能正常提交。员工改代码之前，团队先确认修改范围。

## 跟随这项变更

| 阶段             | 你应能解释什么                               | 阅读或实践                                             |
| ---------------- | -------------------------------------------- | ------------------------------------------------------ |
| 约定工作         | 可以改什么，由谁确认，检查哪些行为           | [编写可验证的需求](/zh-cn/learn/requirements-writing/) |
| 在真实项目中执行 | 哪名员工借助哪些工具和环境完成工作           | [软件工厂概览](/zh-cn/software-factory/overview/)      |
| 用证据作决定     | 检查了哪个版本，哪些行为通过，由谁接受或退回 | [证据与追踪](/zh-cn/software-factory/evidence/)        |

## 深入一个问题

每课都围绕同一项变更，增加一个判断或示例。可以顺序学习，也可以直接打开当前的问题。

1. [什么是 AI 软件工厂](/zh-cn/learn/software-factory-foundations/what-is-ai-software-factory/)：请求怎样连接到可审阅的结果。
2. [智能体工作流如何运作](/zh-cn/learn/software-factory-foundations/how-agentic-workflows-work/)：区分可复用方法与本次执行。
3. [从 Issue 到交付](/zh-cn/learn/software-factory-foundations/from-issue-to-delivery/)：跟随请求，找到人工确认的位置。
4. [智能体、环境与工具](/zh-cn/learn/software-factory-foundations/agents-environments-tools/)：判断执行是否准备就绪。
5. [验证与证据](/zh-cn/learn/software-factory-foundations/verification-evidence/)：识别针对错误版本的验证结果。
6. [人工介入](/zh-cn/learn/software-factory-foundations/human-in-the-loop/)：处理范围变化，并明确交还工作。

## 怎样算完成

你能说清已确认的请求、完成的工作、受检版本与环境，以及审阅决定。你也能解释为什么缺少验证记录，或请求尚未确认时，不能声称交付完成。

看板已准备好时，按[快速入门](/zh-cn/getting-started/quickstart/)实际形成这些记录。需要准备可复用的执行能力时，继续[用 AI Workforce 构建](/zh-cn/learn/build-with-ai-workforce/)。
