证据支持一项结论。追踪是穿过保存这些结论的记录的路径。当审阅者不必猜测哪段聊天“感觉做完了”，就能打开需求、会话、代码引用或 Pull Request、测试结果和发布记录时，软件工厂才有用。

## 把记录分开

| 记录                    | 它能支持的结论                       |
| ----------------------- | ------------------------------------ |
| 已确认的需求            | 约定的范围和验收标准                 |
| 会话                    | 员工被要求做什么，以及哪些工具运行了 |
| Pull Request 或代码引用 | 改变了什么                           |
| 测试或构建记录          | 哪些已配置检查运行了，结果是什么     |
| 运行审计                | 该次调用的自动化状态、输出和错误     |
| 人工决定                | 接受、退回、豁免或接管               |

产物可以有用，同时仍然是错的。一次绿色测试不能证明未检查的标准。合并的 Pull Request 不能证明生产发布。后续记录见[审阅与发布](/zh-cn/software-factory/review-release/)。不在交付卡片上的工作，同一想法见[产物与证据](/zh-cn/user-guide/artifacts-evidence/)。

## 跟住一项变更

从卡片开始。记下会话 ID、代码引用、如果有批次则记下批次，以及决定正文。如果某条记录缺失，依赖它的结论就未经验证。不要补写一次通过。失败时如何找到这些记录，见[可观测性](/zh-cn/software-factory/observability/)。谁调用了运行、平台存了什么，见[审计与合规](/zh-cn/operate/audit/)。
