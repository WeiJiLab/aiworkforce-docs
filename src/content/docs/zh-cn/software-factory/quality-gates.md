质量门禁是工作进入下一条泳道或被视为已接受之前必须成立的条件。在当前工作台里，你实际能用的门禁是已配置的泳道检查和卡片上的人工决定。没有一套单独的策略语言为卡片打分并自动晋升。

## 已经存在的门禁

| 门禁     | 何时前进                                           | 何时退回                         |
| -------- | -------------------------------------------------- | -------------------------------- |
| 需求就绪 | 需求泳道记录 `READY`。看板要求人工确认时已完成确认 | 仍有待澄清事项或待答复的决定     |
| 开发交接 | 会话中的变更记在卡片上                             | 员工被阻塞，或人已接管且尚未交还 |
| 测试结果 | 测试泳道为候选记录了通过                           | 已记录的失败把工作退回修复       |
| 发布审批 | 批次策略要求审批时，人工批准了该动作               | 仍缺少配置要求的审批             |
| 合并     | 项目有可用的仓库集成，且批次符合条件               | 集成或批次记录缺失               |

缺失的检查不是通过。创建卡片不会满足仓库或流水线门禁。测试记录是[构建与测试](/zh-cn/software-factory/build-test/)。与已确认结果的比较是[业务验证](/zh-cn/software-factory/business-verification/)。两者都可以是必需的。谁也不能代替谁。

## 不要用一段话绕过门禁

记录流程例外时，写清跳过的检查、范围、原因和风险。备注或员工指令无法让标准测试门禁通过，泳道仍需要配置所要求的通过结果。合入和生产审批见[发布治理](/zh-cn/software-factory/release-governance/)。
