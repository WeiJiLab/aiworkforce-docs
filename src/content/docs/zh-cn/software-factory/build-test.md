构建与测试是工作台准备候选并记录已配置检查是否通过的阶段。它是关于这些检查的证据。它不是“每条验收标准都被执行过”的声明。

## 泳道记录什么

测试准备把就绪卡片组成候选批次，并准备已配置的测试发布。测试验证成员卡片并记录结果。失败可以按已配置的流程把工作退回修复。在读完当前执行之前，不要另开第二个修复会话。

你可以引用的结果是泳道记录下来的：状态、范围，以及它属于哪次执行。对话里说“测试通过了”不能代替这条记录。如果没有配置流水线，自动阶段就没有运行。照实写。人可以运行一条点名的命令并附上输出，这份输出才是证据。一条不存在的命令不是通过。

## 读批次，不要只读一张卡片

批次共享候选。对批次的操作可能影响每个成员。在为不在候选中的卡片接受一个绿色结果之前，先核对成员。流水线如何连接见 [CI/CD 集成](/zh-cn/software-factory/cicd/)。同一变更与已确认结果的比较见[业务验证](/zh-cn/software-factory/business-verification/)，单元测试未必覆盖它。

失败或缺失的结果可以解开什么，由[质量门禁](/zh-cn/software-factory/quality-gates/)决定。
