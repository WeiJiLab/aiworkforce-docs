软件工厂里的编排，是工作台把卡片和批次沿泳道推进。它不是通用的多 Agent 运行时。每条泳道会话保持自己的执行上下文。当某个阶段（例如测试发布或测试验证）要一起处理多张卡片时，批次把它们组合起来。

## 沿内置泳道查看

内置泳道是需求、开发、测试发布、测试验证、生产发布和已完成。需求确认请求。开发为就绪卡片启动或继续会话。测试发布把就绪卡片组成候选批次。测试验证记录结果，并可以把工作退回修复。生产发布和已完成各自记录结果。自定义看板可以有不同安排。阅读已配置的泳道，不要假设一定是这份清单。分派把卡片交给泳道员工。编排是卡片和批次的这种推进，不是单独的多 Agent 产品。

对共享批次的操作可能影响其中每张卡片。确认前先看成员。开发阶段一次成功的对话只是一条记录。批次的测试和合并记录回答的是别的问题。

## 让人能够停下流程

在卡片上回答问题。如果人接管，自动推进会停止，当前状态会保留。明确交还工作。只恢复暂停并不能清除接管。[Agent 交接](/zh-cn/automate/agent-handoff/)把这种卡片级交接与继续会话、进程内 subagent 作了比较。

编排不授予工具，也不选择运行时。泳道上的员工使用已经配置的授权和运行时。见 [Harness](/zh-cn/software-factory/harness/)和[任务分派](/zh-cn/software-factory/dispatch/)。
