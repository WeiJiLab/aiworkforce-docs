应同时检查资源和执行两个层面的访问控制。成员有权管理工作空间，不代表员工已经获得独立凭据授权；Job 允许运行，也不代表外部供应商会允许所有操作。

## 工作空间与员工访问

工作空间成员关系和资源授权控制员工、会话、Job 及关联记录的访问。管理端点核对当前用户，路由中出现某个用户 ID，不代表可以冒用该用户身份。

代码仓库凭据属于工作空间。员工使用前，平台检查工作空间、供应商实例、启用状态和员工授权；首次启用自动交付时，也会核验相关执行员工授权。Manifest 中的自然语言排除范围有助于明确岗位，但不能授予或撤销真实供应商权限。

仅授予任务所需的上游权限。供应商支持时，读取任务使用只读账号或 Token。发布任务应明确哪个员工、哪条流水线能够写入、合并或部署，并保留流程要求的人工确认。

## 凭据存储与轮换

敏感配置通过后端密钥加密服务保存。签名和加密密钥由部署管理；未经迁移就更改加密密钥，可能使已存值无法读取。普通凭据管理响应只暴露元数据，不返回密钥明文。

Personal Automation Token 独立限制允许调用的 Job，并支持有效期和撤销。设备密钥通过配对流程创建，保存在仅主机账号可访问的 daemon 状态目录。供应商、平台登录与设备凭据应留在各自的存储中，不写进技能正文或共享示例。

撤销员工授权会影响后续授权检查，但不能证明已启动进程停止。删除平台中的供应商凭据，也不会撤销上游 Token。停用访问时应分别记录这些动作。

## 网络边界

远程部署使用 HTTPS，并正确配置信任的反向代理。PostgreSQL 与私有运行控制入口保留在预期网络。自动化 MCP 传输检查允许的 Host/Origin；兼容 MCP 的客户端仍然需要有效凭据和资源授权。

MCP 服务、插件 Hook 或 Shell 工具能够访问其执行环境允许的网络。需要隔离时，应在执行环境配置出站限制。本文档不表示所有工具都自带通用网络沙箱。

## 设备执行与数据流

daemon 以当前操作系统用户身份执行命令。批准的工作目录是上下文边界，不是文件系统沙箱。任务不应接触其他本地数据时，使用专门账号或隔离执行主机。

设备执行期间，模型与 Agent 循环仍在云端平台；提供给任务的工具结果和文件内容，因此可能传到平台及配置的模型供应商。本机执行命令不等于推理仅在本地完成，也不等于数据驻留承诺。

daemon 执行日志可能包含命令与输出数据。恢复时保留未知执行证据，不要通过删除日志清除隔离状态。日志及备份应只对预期主机账号开放。

## 保留与审核

会话、产物、Trace、Issue 观察与交付证据可能包含业务数据。遵循实际部署的保留和删除控制，并单独考虑工作目录及备份。界面资源已删除，不能证明所有上游系统和备份副本都已删除。

启用集成前，核对任务输入范围、输出接收人、模型与运行时供应商、获得授权的员工，以及证据保存位置。这些控制描述产品行为，不代表获得某项合规认证。
