本术语表是使用者、构建者和开发者的共用词汇。技术标识以英文为准。中文解释用产品语言描述同一个概念。

## 共用词汇

| English             | 简体中文   | 含义                                                                           |
| ------------------- | ---------- | ------------------------------------------------------------------------------ |
| Workflow            | 工作流     | 可复用的工作定义。不是自动化的同义词。                                         |
| Automation          | 自动化     | 启动工作流并让后续运行继续发生的机制。在产品里是 Job 加上触发规则。            |
| Job                 | 自动化任务 | 一份自动化定义：任务、一个执行者，以及这个 Job 的触发规则。                    |
| Pipeline            | 编排       | 交付看板某条泳道上的执行器图。至少两个执行器才能启用。                         |
| Agent               | 智能体     | 工作流内部的执行参与者。产品组织模型仍是「工作流 → 自动化 → 智能体」。         |
| AI employee         | 数字员工   | 智能体在工作空间中的已配置形态，不是单独的产品模型；在 Docs 中归入智能体之下。 |
| Employee template   | 员工模板   | 为创建员工而发布的可复用能力。                                                 |
| Employee definition | 员工定义   | 职责、输入、输出和能力要求。                                                   |
| Skill               | 技能       | 针对一类任务的可复用方法。                                                     |
| Plugin              | 插件       | 技能和相关 Agent 的包。                                                        |
| Tool                | 工具       | 执行中的智能体可以调用的一次操作。                                             |
| MCP server          | MCP 服务   | 使用 Model Context Protocol 的外部工具提供方。写上名字不会授予访问权。         |
| Run                 | 运行       | Job 或编排的一次执行实例。                                                     |
| Task                | 任务       | 一个工作单元：收件箱事项、交付卡片或编排节点。                                 |
| Session             | 会话       | 对话以及与之关联的执行上下文。                                                 |
| Runtime             | 运行时     | 运行会话的执行基础设施。                                                       |
| Environment         | 环境       | 执行发生的工作空间资源：仓库、设备和流水线。                                   |
| Artifact            | 产物       | 可以检查的生成或修改结果。                                                     |
| Evidence            | 证据       | 支持某项结论或审阅决定的信息。                                                 |
| Task inbox          | 任务收件箱 | 审阅进入请求的界面。                                                           |
| Issue               | 事项       | 带有自己的来源和审阅状态的被跟踪请求。                                         |
| Delivery workbench  | 交付工作台 | 软件交付卡片沿泳道移动的看板。                                                 |
| Delivery card       | 交付卡片   | 这块看板上的一项工程工作。                                                     |
| Lane                | 泳道       | 带有执行行为的看板列。内置泳道不是手工编辑的状态标签。                         |
| Human review        | 人工审核   | 人对工作的检查和决定。                                                         |
| Dispatch            | 分派       | 把就绪卡片交给该泳道上配置的员工。                                             |
| Orchestration       | 编排推进   | 工作台沿泳道推进卡片和批次。编排界面本身也叫编排。                             |

产品里的**编排**既指编排界面，也在这些文档里用来描述看板推进卡片。句子在说图编辑器时，指的是 pipeline。句子在说卡片前进时，指的是编排推进。[工作流概念](/zh-cn/workflows/concepts/)把两者分开。

## 在上下文里读这些词

员工模板和工作空间员工不同。发布模板是让能力可用。创建员工是在工作空间里初始化一名工作者。

工作流和自动化不同。可以在不启用触发的情况下手动运行工作流。只有触发、没有工作流，只是一个时间或一个事件的名字。

会话、收件箱事项和运行也不同。一次运行可以收集事项。事项仍可能等待审阅。会话可以产出产物，却不能证明请求已经解决。

说输出本身时用**产物**。说支持结论的材料时用**证据**。报告是产物。其中的来源摘录是证据。

工作流验证对照验收标准检查这一次运行。员工评测检查员工包或插件。不要用一个词同时指两者。
