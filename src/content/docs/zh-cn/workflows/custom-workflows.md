自定义工作流是产品已经保存的一种定义。它仍然使用与软件工厂和 Issue 处理相同的自动化、员工、运行和证据。离开内置泳道时，你不需要安装另一套引擎。

## 三种定义

| 定义       | 在哪里编辑                    | 节点可以是什么                               | 如何启动                                    |
| ---------- | ----------------------------- | -------------------------------------------- | ------------------------------------------- |
| Job        | 自动化 → 执行 Job             | 一名员工或一个允许列表中的代码执行器         | 手动、日程、Webhook、GitHub 事件、Issue、IM |
| 泳道编排   | 自动化 → 编排，先选好看板泳道 | 该泳道的 Agent 任务和代码执行器              | 手动或 Cron，且至少两个节点之后才能启用     |
| 技能工作流 | 员工包里，写在技能上的工作流  | 技能、subagent、工具、确认、并行、条件、分支 | 该技能在会话中运行时                        |

编排画布是真实存在的。它不是一张可以脱离看板、描述任意业务流程的画布。创建编排时要选择工作空间、看板和泳道，因为节点是该泳道的执行器。连线可以在成功、失败或无论成败时继续。节点还可以等到 `when` 条件成立、从触发或上游输出映射输入、对列表扇出，并重试。保存之后才启用编排。上游契约变化时，编排会暂停，直到映射被修复。

Job 不会长出这块画布。只有一个执行器时，把触发规则配置在 Job 上。试图启用单个节点时，编排编辑器会这样提示。

## 何时用哪一种

[你的第一个工作流](/zh-cn/getting-started/first-automation/)、定时调研，或 Issue 与 Pull Request 事件，使用 Job。一条泳道必须按顺序运行两个执行器时，使用泳道编排，例如 Agent 任务的输出交给代码执行器结算。分支属于一名员工的方法内部时，使用技能工作流。[Agent 组合](/zh-cn/build/composition/)说明员工包一侧，包括必须在轨迹里看到委派。

## 如何配置一条小编排

1. 在交付看板上确认这条泳道已经有你要串联的执行器。
2. 打开编排，选择工作空间、看板和泳道，然后创建编排。
3. 至少添加两个节点。把每个下游输入映射到触发或上游输出。必填字段不能留空。
4. 把连线设为成功、失败或始终。失败用于兜底，不用于主路径。
5. 保存，阅读契约错误，然后启用。只有这条泳道应按日程运行时才添加 Cron。编排未启用时，Cron 到点也不会启动。
6. 运行一次并打开编排运行。每个节点有自己的状态：等待、已排队、成功、失败或跳过。

## 仍然不能定义的内容

- 循环计数器或无界环。图中的环会被拒绝。
- 不是现有执行器的编排节点。
- 编排自身上的 Webhook、GitHub、Issue 或 IM 触发。把它们放在 Job 上。
- 在制品上限、卡片之间的通用依赖图，或不挂在泳道上的工作流。
- 技能的条件或 subagent 一定执行过。除非轨迹显示它执行了。

## 限制

这里的自定义，指已经保存的 Job、编排或技能定义。它不是一个可以指向任何系统的空工作流类型。如果界面选不到执行器，这条工作流就还不存在。
