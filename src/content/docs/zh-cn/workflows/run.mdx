任务已准备执行，或工作停止后需要判断如何继续时，沿这条路径检查。把原始请求与执行记录保留在一起，让下一步决定有实际发生的工作作为依据。

## 检查就绪条件

启动前，确认任务输入足够、执行者合适、具备所需资源权限，并有能够运行检查的环境。软件变更的交付卡片还需要已确认的范围和验收标准。

[运行时管理](/zh-cn/deployment/runtime-environments/)解释执行位置；[开发环境](/zh-cn/software-factory/environments/)与 [CI/CD 集成](/zh-cn/software-factory/cicd/)说明工程工作需要的资源。

## 跟进一项任务

以表单校验的小修复为例，执行过程中查看卡片关联的会话和代码引用。验证完成时，核对结果对应的版本与环境。必需产物和证据都存在，才进入审阅。

对于 Job，在运行历史中查看状态、输出和关联会话。采集运行成功可能只是创建了收件箱事项；开发开始之前，这项请求仍需确认。

## 处理执行中断

| 观察到的情况         | 下一步                                   |
| -------------------- | ---------------------------------------- |
| 缺少输入或等待决定   | 在约定范围内补充信息或记录决定。         |
| 缺少权限或工具不可用 | 由相应负责人修复连接或授权，再确认就绪。 |
| 验证失败             | 保留失败证据，修复变更，再检查新版本。   |
| 人工接管             | 记录已经完成的动作，准备好后明确交还。   |

重试前核对已有动作，避免重复工作。恢复暂停不会清除接管。请求取消也不能证明远端进程已停止，需要检查实际执行证据。

## 验收结果

审阅者能够找到请求、执行记录、产物，以及覆盖验收标准的证据。使用合并、部署和资源清理阶段时，分别核对这些阶段的结果。

具体控制操作见[运行、结果与恢复](/zh-cn/automate/runs-recovery/)；判断是否接受工作时，继续阅读[证据与追踪](/zh-cn/software-factory/evidence/)。
