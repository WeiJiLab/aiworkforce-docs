AI Workforce 治理让专业数字员工在生命周期中保持安全并且有用。授权、工具权限、模型路由、成本、审计、评测和质量门禁回答的是不同的运营问题，它们围绕同一名员工和同一条交付记录协同工作。

评测是持续过程。一次任务成功，不能证明一个岗位适合重复使用。应保留有代表性的案例，检查它们产生的证据，并在岗位、Skill、知识、工具授权、模型路由或工作流变化后重跑。

## 一名员工，几项决定

| 决定                       | 在哪里作出                                                                              | 提示词不能代替什么   |
| -------------------------- | --------------------------------------------------------------------------------------- | -------------------- |
| 谁可以使用工作空间         | [团队与访问](/zh-cn/administration/teams-access/)                                       | 一个分享链接         |
| 员工可以使用哪些工具和仓库 | 员工授权和[安全与权限](/zh-cn/deployment/security/)                                     | 指令里的“只读”       |
| 工具在哪里运行             | [运行时管理](/zh-cn/deployment/runtime-environments/)                                   | 包里写的一个路径     |
| 用哪个模型、成本是什么     | [模型与成本](/zh-cn/models/overview/)和[平台配置](/zh-cn/administration/configuration/) | 在聊天里输入的模型名 |
| 结果能否继续               | 泳道记录、质量门禁和人工决定                                                            | 一句自信的结束语     |
| 调用了什么                 | 运行历史和[审计](/zh-cn/operate/audit/)                                                 | 一张对话截图         |
| 员工是否仍适合这个岗位     | 重复评测案例和经过审阅的证据                                                            | 一次成功运行         |

去改拥有这次失败的那项控制。轮换登录令牌不会恢复已撤销的仓库凭据。更新模板不会更新已有实例。一张监控图不会验收交付物。

## 运营评测循环

1. 定义岗位使命、验收标准、允许的操作和需要人工接管的条件。
2. 给员工与岗位匹配的最窄授权，并把它路由到部署实际提供的模型。
3. 运行有代表性的案例，覆盖正常请求、输入缺失、超出范围和需要人工接管的情况。
4. 检查任务结果、执行命令、产物、测试、安全发现和交接证据。
5. 在交付工作流中记录决定。当证据显示反复失败时，修改岗位、Skill、上下文、授权或模型路由。
6. 发布或提升修订后的员工之前，重跑同一组案例。

用你能在[用量与分析](/zh-cn/administration/analytics/)里读到的用量来约束工作。质量门禁打开之前要求证据。不要放宽授权来掩盖一个坏结果。
