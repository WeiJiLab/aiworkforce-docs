从失败的最小操作开始。空间权限不足、员工不可用、设备断连、模型渠道故障和回答错误，需要不同处理方式。

## 定位故障层次

| 现象                   | 首先检查                                       |
| ---------------------- | ---------------------------------------------- |
| 无法进入空间或执行操作 | 当前账号、成员身份、授权，以及具体请求的操作。 |
| 员工无法启动           | 初始化状态和界面展示的初始化错误。             |
| 模型不可用             | 当前模型、员工运行时，以及管理员的渠道配置。   |
| 工具或外部来源不可用   | 连接状态、员工授权与外部服务权限。             |
| 设备执行受阻           | 设备在线状态、授权、能力和工作目录。           |
| 结果不完整或错误       | 必需输入、计划、工具返回、产物和验收标准。     |

结果尚不明确时，不要反复创建员工或重复提交操作。先检查已有会话或自动化运行是否已经完成部分工作。

## 检查会话

打开原始会话，阅读可见错误和状态。等待用户回应的会话，可能需要授权决定或补充信息，而不是重启。

出现**查看执行计划**时，用它定位受阻步骤。在会话操作中打开 Debug 模式，检查事件顺序、工具输入预览和返回错误。执行追踪可用时，选择相关运行，查看事件或导出追踪与错误报告。

重试可能修改数据的操作前，先检查真实产物或文件变更。执行中断，也可能已经生成文件或产生外部影响。

## 准备有效问题报告

报告应包含：

- 简短标题，以及预期行为和实际行为。
- 时间与时区、实例地址、最小复现步骤。
- 原始会话 URL，以及相关空间和员工标识。
- 对应界面提供的自动化运行、交付卡片、trace 或 request 标识。
- 当前模型、运行时或设备、权限模式，以及脱敏错误摘录。

不同标识属于不同对象。业务请求 ID 不是 HTTP trace 标识，也不是收件箱事项 ID。保留标识原有名称与来源，避免把所有编号都改称 request ID。

## 升级处理与验证

通过当前实例约定的支持渠道发送报告。管理员可以根据时间关联后端日志和监控。分享前移除凭据、授权请求头、个人文档与无关源码内容。

修复后重复最小复现步骤，核对输出，并记录成功会话或运行。保留原始失败证据，方便复查解决过程。
