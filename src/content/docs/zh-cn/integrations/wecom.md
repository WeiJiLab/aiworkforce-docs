企业微信是面向企业的消息渠道。智能机器人和自建应用可以接收并回复消息。群机器人只能向一个群发通知。企业微信不能代替 Job 或交付看板。

## 它是什么

智能机器人通过 WebSocket 保持连接，不需要公网回调。自建应用接收加密回调，并可向成员发送应用消息。群机器人保存群里的 Webhook 地址，通知发到那里。

## 何时使用

部署不想暴露回调时用智能机器人。希望企业微信来调用部署、并且需要应用消息时，用自建应用。固定群只收通知、不需要回复时，用群机器人。钉钉和微信见[钉钉](/zh-cn/integrations/dingtalk/)与[微信](/zh-cn/integrations/wechat/)。

## 两边交换什么

入站模式可以把消息送到主会话；通过自动化触发时，也可以送到 Job。Job 收到正文、会话 ID 和发送者 ID。群机器人模式向外发通知。它不接收消息，也不能当作自动化的事件来源。

## 如何连接

按使用场景选择入口。**连接消息渠道**保存自动化连接。主会话的**消息渠道**保存主会话绑定。见[消息渠道](/zh-cn/integrations/overview/#消息渠道)。

1. 在企业微信管理后台创建智能机器人、自建应用或群机器人。
2. 在所选入口选择企业微信。
3. 按模式填写凭据。

| 模式       | 要填写的内容                                                          | 回调                                        |
| ---------- | --------------------------------------------------------------------- | ------------------------------------------- |
| 智能机器人 | API 模式里的 Bot ID 和 Bot Secret                                     | 不需要。连接是 WebSocket                    |
| 自建应用   | 企业 ID、应用 Secret、Agent ID、回调 Token，以及 43 位 EncodingAESKey | 公网 HTTPS 地址使用 `/api/im/wecom/webhook` |
| 群机器人   | 连接标识，以及群机器人的 Webhook 地址                                 | 不需要。此模式只发送                        |

回调 Token 和 EncodingAESKey 必须和企业微信消息接收设置一致。群机器人的投递目标必须是该地址背后的群。另外两种模式可以从第一条入站消息得知回复目标，也可以在发通知之前填写用户或群 ID。

## 连接之后能做什么

能到达入站渠道的成员可以和主员工对话。Job 可以选择这条渠道、一个会话 ID，以及最多 100 个发送者 ID。消息订阅必须指定会话 ID。聊天连接不会改变员工的工具和仓库授权。

## 权限与凭据

机器人密钥、应用 Secret、回调 Token 和 EncodingAESKey 随渠道保存。企业 ID 和 Agent ID 用来标识企业应用。在 AI Workforce 里删除渠道，不会删除企业微信应用或群机器人。希望上游密钥失效时，到企业微信里撤销。

## 限制

群机器人听不到回复，也不能启动 Job。自建应用需要公网 HTTPS 回调，加密设置还要和企业微信一致。没有企业微信的事项导入、代码连接或工作流产品。集成的是聊天。工作由 Job 完成。
