工作空间代码仓库是一项具有明确身份和供应商连接的代码资源。应区分仓库身份、访问凭据与员工授权：你自己能够浏览仓库，员工仍可能没有克隆或修改权限。

各家托管的具体步骤在各自页面：[GitHub](/zh-cn/integrations/github/)、[GitLab](/zh-cn/integrations/gitlab/)、[云效 Codeup](/zh-cn/integrations/yunxiao/)。本页是共同的连接规则。GitHub 事件轮询、Projex 导入，以及 Jira 或 Linear 导入，不在本页范围内。

## 支持的连接类型

| 供应商      | 实例信息                                            | 重要边界                                                                   |
| ----------- | --------------------------------------------------- | -------------------------------------------------------------------------- |
| GitHub      | 公共实例或显式配置的企业 HTTPS 域名                 | 内置 PR 查看器支持已连接的 GitHub 仓库，不要假定所有供应商具有相同查看器。 |
| GitLab      | 显式指定的 GitLab 实例地址                          | 实例可访问、仓库可浏览，不代表全部交付适配器都支持该部署。                 |
| 云效 Codeup | 中心版或受支持的 Region 实例；中心版需要原生组织 ID | 选择资源前先匹配版本、实例与凭据供应商。                                   |

实例地址应是 HTTPS 域名，不带用户名密码、仓库路径、查询参数或片段。当前资源模型接受默认 HTTPS 端口。仓库应单独选择，不要把仓库路径追加到实例字段。

## 配置访问

1. 打开工作空间的仓库管理，或从「集成」选择供应商。
2. 创建或选择该供应商、该实例的工作空间凭据。
3. 使用凭据创建连接，浏览其可访问资源。
4. 添加预期仓库，检查克隆地址与默认分支。
5. 显式授权需要使用凭据的员工。
6. 启动一个读取已知文件的小任务，并检查员工返回结果。

凭据属于工作空间。系统记录创建人，但不以创建人作为唯一管理者；当前工作空间访问权限决定谁能够管理元数据和授权。普通管理响应不返回密钥明文。

## 准备自动交付

仓库连接本身不会启用软件工厂。还需配置工作台项目、允许使用的仓库、执行员工及测试发布流水线资源。首次启用自动交付或更换相关员工、Token 绑定时，平台会检查执行员工授权。

运行准备会检查当前工作空间、实例、启用状态与员工授权。撤销授权后，不要继续依赖历史成功记录。员工使用工作空间仓库授权时，个人 Git 凭据不能替代该授权。

## 按层排查

| 现象                     | 检查内容                                       |
| ------------------------ | ---------------------------------------------- |
| 发现列表里没有仓库       | 供应商账号权限、所选命名空间、分页与连接实例。 |
| 凭据可见但不可选         | 启用状态、供应商与实例匹配、连接当前实例。     |
| 用户能浏览，员工不能执行 | 员工显式授权，以及会话或泳道实际使用的员工。   |
| 无法开始交付             | 项目仓库选择、岗位绑定、授权与流水线能力。     |
| 删除凭据被阻止           | 先移除员工授权和仓库连接引用。                 |

删除平台凭据不会撤销供应商端 Token，也不会终止已经运行的会话。如需撤销上游密钥，应在供应商处轮换或撤销。
