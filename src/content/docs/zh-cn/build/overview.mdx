团队反复需要同一类工作时，可以构建可复用 AI Worker，例如需求澄清、架构审阅或指定测试流程。从一项真实任务开始，请专家说明其中的判断、检查点和验收标准。

最终得到的是有版本的能力，工作空间可以采用它；职责、工具依赖和判断结果的证据都有明确约定。

## 从工作本身开始

以测试报告审阅员为例，先约定它读取哪些报告、什么算发现问题，以及需要提交什么。专家提供示例和必需检查，构建者或 FDE 将它们整理为指令和工作方法，接入工具，再与专家一起用真实任务试验。

先写清预期输出，再选择工具。例如，验收可以要求每项发现都标出来源，并说明影响哪项需求。同时约定哪些例外交给人处理。

## 构建并检查一个版本

| 要作出的决定                                 | 对应指南                                                                                    |
| -------------------------------------------- | ------------------------------------------------------------------------------------------- |
| 角色负责什么，哪些工作超出范围？             | [员工定义](/zh-cn/build/employee-definition/)                                               |
| 需要哪些工作方法和工具？                     | [技能与插件](/zh-cn/build/skills-plugins/)及[工具连接](/zh-cn/integrations/employee-tools/) |
| 正常输入、缺少输入和越界请求下能否正确工作？ | [员工测试](/zh-cn/build/testing/)                                                           |
| 团队如何取得并采用这个版本？                 | [发布与分发](/zh-cn/build/publishing/)                                                      |

指令中写出工具名称不会授予访问权。应检查工作空间中的实际实例、连接和权限。能力包校验检查结构；任务试验和专家审阅判断角色是否达到验收标准。

## 怎样算准备好

审阅者能够识别版本、重复任务试验，并检查输出和依据。所需工具能在约定权限内使用，也有人知道如何处理例外。

发布模板后，团队可以使用它。已有员工不会自动采用后续模板变更。记录团队实际使用的版本，把可复现的失败交回构建者，用于下一次试验。

从[员工定义](/zh-cn/build/employee-definition/)开始。已有合适模板时，直接[创建工作空间员工](/zh-cn/getting-started/first-employee/)并检查第一次任务结果。
