子 Agent 负责一项有边界的专门工作；Hook 在运行时事件发生时执行逻辑。两者都会影响执行，但用途不同：需要推理并返回可审阅结果时使用子 Agent，需要确定性的运行时响应时才考虑 Hook。

## 定义专注的子 Agent

Agent 包可以在 `agents/*.md` 中包含子 Agent 文档，文件名就是包内流程引用使用的标识。例如创建 `agents/source-reviewer.md`：

```markdown
---
name: source-reviewer
description: 检查研究简报中的结论是否有提供的来源支持。
---

阅读提供的简报和来源摘录。
逐项返回：有支持、无支持或不确定，
附对应来源引用与简短理由。
不要获取其他来源，也不要发布简报。
```

在入口技能中说明委派什么材料、子 Agent 应返回什么，以及父 Agent 如何检查结果。提供完成工作所需的证据，不要假定子 Agent 已经知道父会话的所有消息。

包扫描器读取技能和子 Agent 文档，并解析受支持的 `awf` 流程围栏。流程引用必须指向已有技能或子 Agent，每个流程需要唯一的终止 `return`。展示的流程图描述包的结构，不能证明所有动作已经成功执行。

## 验证交接

使用包含一项有来源支持、一项无支持及一项来源含糊的简报测试。确认子 Agent 返回的区分结果能够被父 Agent 使用，并从执行轨迹检查真实委派和父 Agent 的最终综合。仅在正文中提到子 Agent，不能证明运行时真的调用了它。

包内子 Agent 也不等于单独创建的工作空间员工。跨员工分派、交付泳道交接和运行时内部子 Agent 调用具有不同的状态与授权边界。

## 理解 Hook 支持

Claude Code 集成为工具授权、重复工具调用保护、MCP 输出脱敏和文件变更恢复点等平台功能挂载事件 Hook。运行时还使用其支持的用户、项目和本地配置来源。导入的插件 Manifest 可以包含 Hook 资产，具体语法和执行行为依赖所选运行时版本。

平台没有保证所有运行时行为一致的通用 Hooks 编辑器。使用插件 Hook 前，应检查运行时支持的 Hook 契约、调用命令、依赖、工作目录及失败行为，并在隔离工作空间中用员工实际使用的运行时测试。不要把平台 Hook 内部实现复制进包，也不要假定已安装插件的 Hook 可以直接移植到其他运行时。

## 选择适合的机制

| 需求                   | 使用机制                   |
| ---------------------- | -------------------------- |
| 可重复的工作方法       | Skill。                    |
| 专门分析并返回父 Agent | 子 Agent。                 |
| 定时或外部事件         | 自动化触发规则。           |
| 运行时生命周期行为     | 兼容且经过审核的 Hook。    |
| 继续前需要人工决定     | 产品的审批或人工介入流程。 |
