工具是运行时可以执行的操作：读取文件、调用 MCP 工具，或记录收件箱事项。声明岗位需要这个工具，并不允许这次调用。授权是员工实例、设备或外部账号上的另一项决定。

本页面向决定岗位应依赖哪些工具的构建者。在产品里检查已有连接的人应使用[工具与连接器](/zh-cn/integrations/employee-tools/)。

## 声明、配置、授权

| 步骤 | 它做什么                       | 它不做什么                 |
| ---- | ------------------------------ | -------------------------- |
| 声明 | 写出岗位期望的工具或 MCP 服务  | 授予访问或保存密钥         |
| 配置 | 提供应用到实例的连接           | 证明外部账号仍然可用       |
| 授权 | 允许这名员工使用某项凭据或设备 | 授权工作空间中的每一名员工 |

Skill 可以说明何时调用工具。措辞不是授权。选择能完成职责的最窄工具。一份研究简报不需要发送邮件的工具。应该打开 Pull Request 的交付员工，需要这名员工自己的仓库授权，而不仅是工作空间上的仓库连接。见[代码仓库](/zh-cn/integrations/code-repositories/)。

## 检查一次调用

把包应用到测试实例。查看员工上的工具，完成所需的账号连接，并执行一次与岗位匹配的读取。工具缺失意味着配置没有到达实例、账号未授权，或两个来源在同一个服务名上冲突。修来源。不要把密钥写进 Skill 文件。

设备工具只有通过会话的设备授权才可用。员工包不能靠写一个路径来授予自己设备。云端业务连接接受 HTTP/SSE MCP 服务。编辑器支持 MCP，并不代表每种认证方式都可用。见 [MCP 集成](/zh-cn/integrations/mcp/)。

撤销授权会改变之后的检查。它不能证明已经启动的进程已经停止。移除访问时记下这个限制。操作者侧的同一边界见[安全与权限](/zh-cn/deployment/security/)。
