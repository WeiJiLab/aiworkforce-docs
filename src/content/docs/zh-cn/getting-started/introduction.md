AI Workforce 是以工作流为中心的平台。工作流定义工作如何完成。自动化启动这条工作流并让它持续运行。数字员工是执行步骤的智能体。人仍然对范围、接管和发布负责。

同一套模型覆盖一次性任务、来自 GitHub 的事件、日程，以及持续消耗卡片的交付看板。软件工厂、看板工作台和 Issue 处理是这个模型的应用。它们不是三个产品。

## 选择路径

- **运行第一个工作流。** 按[你的第一个工作流](/zh-cn/getting-started/first-automation/)创建 Job，检查一次手动运行，然后再启用触发规则。需要稳定用词时阅读[工作流概念](/zh-cn/workflows/concepts/)。
- **使用员工。** 按[快速开始](/zh-cn/getting-started/quickstart/)或[构建你的第一个数字员工](/zh-cn/getting-started/first-employee/)，从已发布模板创建员工。然后使用[工作空间](/zh-cn/user-guide/workspace/)和 [Agent 对话](/zh-cn/user-guide/agent-chat/)。
- **交付软件。** 当已确认的请求必须经过执行、验证、证据和人工发布决定时，打开[软件工厂](/zh-cn/software-factory/overview/)和[看板工作台](/zh-cn/workflows/kanban-workbench/)。
- **响应 Issue。** 用 [Issue 自动化](/zh-cn/workflows/issue-automation/)接收 GitHub Issue 或收件箱事项。开发开始之前先确认。

构建者定义可复用的员工。使用者从已发布模板创建工作空间员工。自动化要求一名就绪的员工执行工作。看板在交付工作流里使用这些员工。员工包的编写步骤在[构建数字员工](/zh-cn/build/employee-definition/)里，不在使用指南里。

## 开始之前

你需要某个 AI Workforce 部署上的账号，以及一个工作空间的访问权。工作空间管理员提供模板、执行资源和连接。可用能力取决于该部署。本文档把部分支持标为**部分支持**，把当前版本尚未提供的能力标为**规划中**。

第一次任务请使用你可以分享的小段输入，并要求带有明确验收标准的书面输出。这样才分得清流畅的回答和经过验证的结果。

## 怎样算完成

你可以打开工作空间，用一名就绪的员工开始会话，交给它一个有边界的任务，并审阅回答或生成的文件。当这项任务还应再次发生时，你有一个 Job、一次检查过的运行，以及至多一条你知道去哪里找的触发规则。当任务会修改软件时，开发开始之前，请求已经是一张已确认的交付卡片。

如果员工无法启动，检查初始化，并请工作空间管理员查看执行配置。如果回答缺少依据，接受之前先要求来源或验证步骤。
