AI Workforce 是面向企业的 AI 研发协作与交付平台。它把专业数字员工、人、项目知识、工程系统和交付证据组织在一条从需求到开发、测试、安全与发布的路径上。

平台由三层组成：

- **专业数字员工**把研发岗位转化为可复用的生产力。需求助手、架构助手、开发助手、测试助手和安全审阅助手都可以拥有明确职责、工具、知识、权限和验收标准。
- **研发协作与交付体系**通过工作空间、任务、交付看板、协作模板和工作交接，把人和员工组织到同一项工作上。团队可以从已确认的需求推进到实现、验证、安全审阅和发布。
- **企业级运行底座**提供会话、执行环境、模型端点、集成、访问控制、审计、评测和证据记录，让 AI 能够在真实研发环境中工作。

长期方向是一个通过持续积累交付证据不断改进的智能软件工厂。当前产品已经通过[专家工作台](/zh-cn/user-guide/expert-workbench/)、[软件工厂](/zh-cn/software-factory/overview/)和企业部署控制提供了这条方向所需的基础能力。

## 从一项可验证的交付开始

同一套平台模型覆盖一次性任务、来自 GitHub 的事件、日程，以及持续消耗卡片的交付看板。这些都是由同一组员工、自动化、会话和证据构成的工作流应用。

[开始使用](/zh-cn/#开始使用)时，先选择一项带有验收标准的小请求。需要人与一名专业员工协作时，使用专家工作台完成安全审阅、代码审阅或测试证据检查。需要多个岗位把变更从需求推进到发布时，使用交付工作台。

[软件工厂](/zh-cn/software-factory/overview/)连接四条交付回路：[需求到卡片](/zh-cn/software-factory/requirements-to-card/)、[卡片到 Pull Request](/zh-cn/software-factory/card-to-pr/)、[Pull Request 到合并](/zh-cn/software-factory/pr-to-merge/)，以及[信号回到卡片](/zh-cn/software-factory/signal-to-card/)。卡片把已确认的需求、实现、验证证据、安全发现和人工决定连在一起。

构建者定义可复用的员工。工作空间使用者从已发布模板创建员工。自动化或人可以分配工作。交付体系把结果交给下一阶段。要编写 Agent 包，请参阅[定制与扩展](/zh-cn/build/)。

## 开始之前

你需要某个 AI Workforce 部署上的账号，以及一个工作空间的访问权。普通成员（`NORMAL_USER`）登录后进入**工作台**，没有 **FDE 工作台**，也没有**管理控制台**。数字员工模板缺失时，由 FDE 用户或系统管理员发布。协作模板缺失时，由系统管理员发布。员工起不来时，请能管理该空间数字员工的人检查。改授权由空间创建者、团队 leader 或管理员进行。没有名为 workspace manager 的账号。角色见[团队与访问权限](/zh-cn/administration/teams-access/)。交付工作流还需要仓库连接、就绪的泳道员工，以及验证变更的方法。可用能力取决于该部署。当前版本尚未提供的能力标为**规划中**。

第一次软件变更请使用一条小 Issue，并写上审阅者能够核对的验收标准。如果第一次任务不会修改软件，请使用你可以分享的小段输入，并要求带有明确验收标准的书面输出。

## 怎样算完成

对于软件变更，审阅者能够打开已确认的需求，识别被检查的版本，阅读测试和安全结果，并看到团队是接受了变更还是退回修复。当工作还应在没有看板的情况下再次发生时，你有一个 Job、一次检查过的运行，以及至多一条你知道去哪里找的触发规则。开发开始之前，请求必须已经是一张已确认的交付卡片。

如果员工无法启动，检查初始化，并请能管理该空间数字员工的人查看执行配置。如果回答或代码变更缺少依据，接受之前先要求来源或验证步骤。
