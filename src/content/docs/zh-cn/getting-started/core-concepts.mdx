沿用[快速入门](/zh-cn/getting-started/quickstart/)中的小变更：修正一条表单提示，检查空字段和有效输入两种情况，再记录审阅决定。下面的概念描述这项工作的不同部分。

## 先掌握这些词

| 概念               | 回答的问题         | 表单示例中的对应内容                         |
| ------------------ | ------------------ | -------------------------------------------- |
| 任务               | 要得到什么结果？   | Issue，以及随后确认的提示修改卡片            |
| 工作流             | 这项工作如何完成？ | 约定的开发、验证和审阅过程                   |
| 智能体 / AI worker | 谁执行步骤？       | 指派给泳道、已配置的工作空间员工             |
| 自动化             | 什么启动工作？     | 手动操作或已配置的触发；Job 定义任务和执行者 |
| 运行               | 这一次发生了什么？ | 一次 Job 或编排执行，以及它的状态和结果      |
| 证据               | 凭什么接受结果？   | 变更、受测版本、环境、测试结果和审阅决定     |

**工作空间**把一起协作的人、员工、资源和上下文放在一处。能访问工作空间，与获准使用具体资源，是不同的授权。

## 可复用的工作与一次执行

<ProcessDiagram id="automation-run" />

修改或发布任务定义，不能证明某次运行的结果。审阅时需要检查对应执行记录和支持该结果的证据。

工作流可以表现为交付看板的泳道和规则、某个泳道上的编排，或员工技能中声明的流程。[工作流概念](/zh-cn/workflows/concepts/)说明如何选择这些形式。

## 执行者与能力

已发布的**模板**提供可复用岗位。工作空间中的**员工**是初始化完成后由团队实际指派的实例。**Skill** 描述可复用方法，**Plugin** 打包技能和相关 Agent。**工具**执行操作，**MCP 服务**暴露外部工具。

指令描述期望行为，实际调用工具仍需要运行时、连接和授权。[构建可复用 AI worker](/zh-cn/build/overview/)说明如何把这些部分组合成团队可以使用的能力。

## 按记录的用途判断结果

**会话**保留对话和执行上下文。**产物**是代码、报告等输出。证据支持对产物的判断。交付卡片把需求、执行和决定关联起来；创建卡片不会准备仓库或流水线。

例如，一次成功的自动化运行可能只是收集了 Issue，对应交付卡片仍在等待确认范围。同样，会话结束或 PR 合并后，还需要分别核对验证和部署记录。

更多术语见[术语表](/zh-cn/concepts/glossary/)，查找界面时使用[平台地图](/zh-cn/getting-started/platform-overview/)。
