一条 Issue 可以先进入收件箱，再转成交付看板上的草稿。团队确认需求后进入开发。软件工厂推进交付，自动化根据触发规则发起工作，数字员工按授权执行，团队依据证据决定下一步。

在会话、收件箱事项、自动化运行和交付卡片里使用同一套词。这些记录可能显示不同状态，因为它们回答的问题不同。

## 五个抽象

| 抽象     | 它回答的问题                     | 你要查看的内容                   |
| -------- | -------------------------------- | -------------------------------- |
| 软件工厂 | 工程工作如何到达经过审阅的交付？ | 进入、执行、验证、证据和发布     |
| 自动化   | 什么启动工作，启动之后发生什么？ | Job、触发规则和一次运行          |
| 数字员工 | 谁执行分派的工作？               | 岗位、工作空间实例和就绪状态     |
| 能力     | 这个员工可以使用哪些方法和工具？ | Skills、Plugins、工具和 MCP 依赖 |
| 治理     | 什么被允许、被证明、被放行？     | 权限、评测、证据和人工决定       |

工作空间把一起使用的员工、资源和工作上下文组织在一起。能进入工作空间，与能管理空间或执行工作，是不同权限。

## 它们如何组合

**软件工厂**通过看板推进研发交付。由人确认草稿卡片上的需求后，泳道员工可以实现变更并准备验证。团队审阅证据，决定变更是否可以合并或发布。见[软件工厂](/zh-cn/software-factory/overview/)。

**自动化**把外部信号或日程转成工作。Job 定义任务和执行者。日程、Webhook、平台事件、Issue 或 IM 消息都可以触发 Job，具体取决于部署支持的类型。每次执行都会生成一条运行记录，供团队检查。见[自动化概念](/zh-cn/automate/fundamentals/)。

**数字员工**是执行主体。已发布的模板提供可复用岗位；工作空间里的员工才是你实际分配任务的实例。初始化完成后，会话才有意义。创建实例并不是在编写模板。构建者在[构建数字员工](/zh-cn/build/architecture/)中定义岗位；使用者在[使用数字员工](/zh-cn/user-guide/ai-employees/)中选择员工并分配任务。

**能力**是这个主体的工作方式：

- **Skill** 是某一类任务的可复用方法。
- **Plugin** 打包 Skills 和相关 agents。
- **工具**执行一项操作。
- **MCP 服务**提供外部工具。在员工清单里写上服务名称，只是声明依赖，不会保存凭据，也不会授予访问权。

指令描述预期行为。运行时和授权决定哪些工具真正执行。完整组成见[员工架构](/zh-cn/build/architecture/)。员工侧的依赖见 [MCP 服务](/zh-cn/build/mcp-integration/)。协议和连接方法见 [MCP 集成](/zh-cn/integrations/mcp/)。

**治理**把权限、评测和证据连在一起。提示词里写“只读”不能代替工具授权。一次顺利的对话不能代替测试结果或验收决定。改变范围、接管执行或发布软件的决定仍由人作出。

## 必须分开的记录

| 记录             | 它证明什么                               |
| ---------------- | ---------------------------------------- |
| 会话             | 围绕一个目标的对话和执行上下文           |
| 收件箱任务或事项 | 被跟踪的请求、来源和审阅状态             |
| 自动化运行       | Job 的一次调用，包括失败和恢复           |
| 产物             | 一份输出，例如报告或文件                 |
| 证据             | 对结论的支持：来源、测试、关联会话或差异 |
| 交付卡片         | 在已配置看板上推进的工程工作             |

产物可以有用，但不因此正确。收件箱里的事项不是修改代码的批准。交付卡片把需求、执行和人工决定放在一起；卡片存在，并不等于仓库或流水线已经配置好。

## 共享的层次

其余文档使用的六层，对应上面的五个抽象：

| 层次         | 包含                    |
| ------------ | ----------------------- |
| 员工能力     | 员工、Skills、Plugins   |
| 执行         | Agent、Harness、Runtime |
| 编排         | 自动化与任务分派        |
| 工程基础设施 | 环境与 CI/CD            |
| 质量保证     | 验证、证据、评测        |
| 工作管理     | 收件箱、产物、项目      |

[平台概览](/zh-cn/getting-started/platform-overview/)说明各个概念对应的产品界面。[术语表](/zh-cn/concepts/glossary/)提供中英文术语。按[快速入门](/zh-cn/getting-started/quickstart/)在交付工作台上走通一条 Issue。
