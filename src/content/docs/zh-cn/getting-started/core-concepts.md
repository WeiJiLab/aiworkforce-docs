AI Workforce 把专业数字员工、交付工作流和企业级运行底座放在同一套系统里。会话、收件箱事项、自动化运行和交付卡片使用同一套词。这些记录可以显示不同状态，因为它们回答的问题不同。

软件变更的默认路径是交付看板上的一张已确认卡片。Issue 可以先进入收件箱，再转入这张草稿。开发在确认之后才开始。

岗位模板定义团队可以委派的那部分职责。工作空间中的员工实例按本项目的授权接单。工作流说明任务如何推进，触发规则决定何时启动。每项任务按自己的验收标准检查结果。

## 核心记录

| 记录   | 它回答什么                           | 你检查什么                             |
| ------ | ------------------------------------ | -------------------------------------- |
| 工作流 | 这类工作应当如何完成？               | 看板泳道、泳道编排，或技能工作流       |
| 自动化 | 什么启动它，又是什么带来下一次运行？ | Job 或编排触发。它不是工作流的同义词。 |
| 智能体 | 谁执行一步？                         | 数字员工，或泳道上的代码执行器         |
| 运行   | 这一次发生了什么？                   | 一次 Job 运行或一次编排运行            |
| 任务   | 工作单元是什么？                     | 收件箱事项、交付卡片，或编排节点       |
| 证据   | 凭什么说工作已经完成？               | 会话、差异、测试和人工决定             |

工作空间把一起使用的员工、资源和上下文放在一处。能进入工作空间，不等于能管理它或执行工作。

## 它们如何配合

**工作流**是可复用的。在交付看板上，它是泳道及其规则。在自动化的编排里，它是该泳道执行器组成的图。在 Agent 包里，它是技能上声明的工作流。[工作流概念](/zh-cn/workflows/concepts/)是完整地图，包括界面上没有的部分。

**自动化**是 Job 或编排触发。触发可以是手动、日程、Webhook、轮询到的 GitHub 事件、Issue、IM 消息，或看板发现一张就绪卡片。发布不会创建运行。见[自动化概念](/zh-cn/automate/fundamentals/)。

**数字员工**是执行者。已发布模板提供可复用岗位。工作空间员工是你实际指派的实例。初始化完成之前，会话没有用。构建者在[Agent 定义](/zh-cn/build/employee-definition/)里写岗位。使用者在[数字员工](/zh-cn/user-guide/ai-employees/)里选择已发布员工。

**能力**是这个执行者的工作方式：

- **Skill** 是针对一类任务的可复用方法。
- **Plugin** 打包技能和相关 Agent。
- **工具**执行一次操作。
- **MCP 服务**暴露外部工具。在员工清单里写上服务名，只是记录依赖。它不保存凭据，也不授予访问权。

指令描述期望的行为。运行时和授权决定哪些工具真正运行。

**软件工厂**把已确认的工程请求送过看板。它和 Issue 处理、定时工作一样，是一种[工作流应用](/zh-cn/workflows/applications/)。它不是「Agent 会无人值守地写完代码」的承诺。

## 能力、控制与证明

| 需要       | 它在哪里                 | 不要把它当成                            |
| ---------- | ------------------------ | --------------------------------------- |
| 分派       | 把就绪卡片交给泳道员工   | 编排。编排是沿泳道推进卡片和批次。      |
| 编排       | 工作台和泳道编排         | 通用的多 Agent 运行时                   |
| 工作流验证 | 测试、验收标准和人工比较 | 员工评测。评测检查的是 Agent 包或插件。 |
| 产物       | 文件、报告或代码变更     | 证据。证据是你相信这份产物的理由。      |
| 运行时     | 会话在哪里执行           | 环境中的仓库、设备和流水线              |

提示词里写「只读」不能代替工具授权。一段顺利的对话不能代替测试结果。改变范围、接管执行或发布软件的决定仍由人作出。

## 必须分开的记录

| 记录               | 它证明什么                                     |
| ------------------ | ---------------------------------------------- |
| 会话               | 一个目标的对话和执行上下文                     |
| 收件箱任务或 Issue | 被跟踪的请求、它的来源和审阅状态               |
| 自动化运行         | 一次 Job 调用，包括失败和恢复                  |
| 编排运行           | 一次经过泳道编排的过程，每个节点有自己的状态   |
| 产物               | 一份输出，例如报告或文件                       |
| 证据               | 支持某项结论的材料：来源、测试、关联会话或差异 |
| 交付卡片           | 在已配置看板上移动的工程工作                   |

产物可以有用但不正确。收集到的收件箱事项不是修改代码的许可。交付卡片把需求、执行和人工决定放在一起。卡片不会配置仓库或流水线。
