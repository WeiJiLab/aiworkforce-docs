从一个还没有交付看板的工作空间开始。创建看板，准备执行所需的仓库和测试资源，然后验证一项小改动。如果看板已经配好，请直接进入[快速入门](/zh-cn/getting-started/quickstart/)。

## 开始之前

你需要在目标工作空间拥有创建交付看板、管理仓库和员工授权的权限。准备一个获准使用的测试仓库、可以验证变更的测试环境，以及包含需求、开发和验证阶段的已发布看板模板。看板模板缺失时请系统管理员发布。不能添加泳道员工时，页面写的是联系空间管理员。参考[创建数字员工](/zh-cn/getting-started/first-employee/)，为每条必配泳道准备一个已就绪的员工实例。

## 1. 准备仓库和执行权限

1. 在工作空间打开**代码仓库**。通过**管理仓库连接**选择与测试仓库提供方及实例匹配的连接，或使用已获准的工作空间凭据创建连接。选择**添加代码仓库**，核对克隆地址和默认分支。
2. 按[代码仓库](/zh-cn/integrations/code-repositories/)的步骤，为开发泳道员工授予使用对应仓库凭据的权限。其他泳道员工如需访问仓库，也检查各自的授权。先用一个小型读取任务确认访问，再让开发员工修改代码。
3. 检查就绪的员工能在预期的[开发环境](/zh-cn/software-factory/environments/)中运行。如果希望交付 GitHub Pull Request，核对仓库连接和员工授权是否允许创建分支和 PR。

## 2. 创建交付看板

1. 在主导航打开**工作台**。交付工作台的地址是 `/automations?tab=board-flow`。选中目标工作空间，点击**新建交付项目**，进入**创建看板**向导。
2. 在**选择模板**中选用已发布的交付模板。在**基本信息**填写看板名称并核对泳道顺序。在**数字员工**中给每条必配泳道分配一名已就绪的员工。
3. 在**共享 MCP 与 Skill**中核对模板预选的工具和技能。首次试跑可跳过**外部看板与工作项来源**中的外部同步和来源配置，直接从任务收件箱转入 Issue，或在看板中新建需求会话。
4. 在**确认创建**中核对配置，点击**创建看板**。模板中的自动化可能在初始化通过后启用，创建前请确认选的是测试工作空间和适用的模板。初始化完成后点击**进入看板**。某个模块失败时可以单独重试，如需调整输入，可选择**返回配置**。

尚未保存的新项目在看板设置里显示**观察模式**。页面写着：「新项目先保存为观察模式 · 检查通过后再启动。」先检查配置，再启动项目。

## 3. 核对泳道与测试方式

1. 在**看板设置**确认项目已绑定测试仓库。如果创建时跳过了外部 Issue 来源，先绑定仓库，再添加该来源。打开**泳道配置**，检查每条必配泳道的**执行身份**，然后在**泳道流程**核对员工绑定和已保存的自动化。
2. 如果看板需要运行自动检查，为项目连接测试流水线，核对实际使用的测试部署或环境。例如，已连接的 GitHub 仓库可以使用 GitHub Actions 工作流作为项目流水线。配置方法见 [CI/CD 集成](/zh-cn/software-factory/cicd/)和 [GitHub](/zh-cn/integrations/github/)。从配置好的测试发布和测试验证泳道查看运行结果。
3. 如果自动检查暂不可用，选一项可在测试环境实际执行的检查，并记录哪些自动检查未运行。在所需结果齐备或团队记录明确豁免前，保留相关门禁的阻塞状态。参见[质量门禁](/zh-cn/software-factory/quality-gates/)。

## 4. 验证第一张卡片

1. 使用[从 Issue 到 PR](/zh-cn/recipes/issue-to-pr/)中的表单校验示例。可以从任务收件箱转入 Issue。如果看板以需求泳道为入口，也可以点击**新建需求会话**提出这项变更。开始开发前，在草稿上确认预期行为、验收标准和允许修改的仓库。确认需求不会同时批准修改仓库，也不会授予凭据。
2. 跟进卡片的开发阶段。在**执行记录**中查看处理变更的会话，在**交付物**中打开代码引用。若项目配置的交付路径创建了 Pull Request，可以从这里检查 PR。
3. 在测试环境验证示例的两条行为。留空时显示修正后的提示，填写有效值时仍可提交。记录实际测试的提交或候选版本、环境以及每项验收结果。检查失败时，附上证据并退回修复，随后验证新版本。在卡片上记录审阅决定。

当第一张卡片具备已确认的需求、执行记录、代码引用、对应版本的验证证据和人工审阅决定时，就可以开始下一项交付。卡片停止推进时，参见[排查交付看板](/zh-cn/getting-started/delivery-board-troubleshooting/)；要继续跟进审阅后的步骤，参见[审阅与发布](/zh-cn/software-factory/review-release/)。
