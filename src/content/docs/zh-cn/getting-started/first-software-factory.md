配置软件工厂看板，或排查卡片为何停止推进时，可以按本页检查。如果看板已就绪，想先走通一项 Issue，请从[快速入门](/zh-cn/getting-started/quickstart/)开始。

## 前提

在 **Automations** 中打开**交付工作台**（`/automations?tab=board-flow`）。在目标工作空间选中[交付项目](/zh-cn/user-guide/projects/)，检查本次要使用的交付阶段。

| 检查项         | 需要确认什么                                                                                                                           |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 看板与泳道     | 找到团队确认需求、启动开发和审阅测试结果的位置，确认当前看板提供哪些操作。                                                             |
| 仓库与授权     | 确认仓库连接已启用且属于目标工作空间，逐一核对执行员工是否持有所需的仓库授权。参见[代码仓库](/zh-cn/integrations/code-repositories/)。 |
| 执行就绪       | 确认分配到相关泳道的员工已在配置的运行时中就绪。参见[任务分派](/zh-cn/software-factory/dispatch/)。                                    |
| 测试与发布资源 | 检查各阶段配置的 [CI/CD 集成](/zh-cn/software-factory/cicd/)和执行环境。合并和生产发布各自需要可用的仓库和流水线集成。                 |

## 1. 开发之前先确认请求

在草稿卡片上确认要做的变更、审阅者可核对的验收标准，以及允许改动的仓库。标准有歧义时，让卡片保留在草稿状态，并在卡片上澄清。需求就绪后，从卡片发起或继续开发，确保执行会话与需求关联。

## 2. 恢复受阻的卡片

先查看卡片当前所处的泳道、正在进行的执行和待回答的问题，再决定如何继续。

| 卡片受阻的情况         | 检查或处理方法                                                                   |
| ---------------------- | -------------------------------------------------------------------------------- |
| 员工需要补充信息或确认 | 查看卡片上的请求，回复决定及其范围。                                             |
| 执行无法访问所需仓库   | 先检查项目的仓库连接和执行员工的授权，再恢复工作。                               |
| 有人接管了卡片         | 记录已处理的事项，并明确交还卡片才能继续自动推进。恢复暂停后，接管状态仍然有效。 |
| 测试失败               | 检查失败记录和正在进行的修复，通过配置的泳道退回变更。修复后验证新版本。         |

对共享测试批次执行操作前，先核对批次内的所有卡片。如果是采集需求的 Job 运行失败，参见[运行、结果与恢复](/zh-cn/automate/runs-recovery/)。

## 3. 要求验证和证据

对照卡片的验收标准，核对代码引用、受测版本、环境和测试结果。记录每项必需检查的结果。流水线未能执行时，说明实际情况，并附上单独执行的检查结果。审阅者豁免某项检查时，应记录原因、适用范围和剩余风险。参见[证据与追踪](/zh-cn/software-factory/evidence/)和[质量门禁](/zh-cn/software-factory/quality-gates/)。

## 4. 跟进合并、发布和资源清理

项目已配置合并和发布时，分别查看这些阶段的执行结果。批次关闭时，核对记录中的合并结果。通过发布记录确认到达目标环境的版本，再通过清理记录确认交付资源已释放。参见[审阅与发布](/zh-cn/software-factory/review-release/)。

## 预期结果

团队能找到项目配置的交付阶段、承接需求的卡片和会话，以及说明工作为何就绪、受阻或完成的记录。可以用[从 Issue 到 PR](/zh-cn/recipes/issue-to-pr/)在一项小改动上练习。
