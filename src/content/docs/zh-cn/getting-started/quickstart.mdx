用软件工厂把任务收件箱里的一项小需求推进到可审阅的代码变更。本教程以修正表单校验提示为例：项目名称留空时显示「请输入项目名称。」填写有效名称时仍能正常创建项目。

## 确认你的起点

- **看板已就绪：**使用已配置交付项目和看板的工作空间，确认其中有[已连接的代码仓库](/zh-cn/integrations/code-repositories/)，以及运行检查所需的测试环境或流水线。相关泳道的员工需要就绪，并获得仓库访问授权。确认你有权限确认和审阅卡片。
- **尚未准备好：**先按[配置并运行交付看板](/zh-cn/getting-started/first-software-factory/)完成准备，再回到本教程第 1 步。

也可以先[查看完整示例](/zh-cn/recipes/issue-to-pr/)来了解预期的交付记录。

## 最后要审阅什么

<ProcessDiagram id="delivery-loop" />

完成后，应能打开卡片核对以下记录。这些是审阅问题，无需另外创建一张表单。

| 审阅项     | 表单示例                               |
| ---------- | -------------------------------------- |
| 已确认需求 | 必填字段为空时显示约定的提示           |
| 正常行为   | 有效输入仍能正常提交                   |
| 代码引用   | 代码引用，以及实际检查的提交或候选版本 |
| 验证       | 两项验收标准对应的环境和结果           |
| 决定       | 接受变更，或附未通过项与证据退回修复   |

## 1. 在交付看板上确认 Issue

打开工作空间的**任务收件箱**，检查 Issue 后将其转入目标交付项目。打开生成的草稿，通过卡片上的人工确认请求，确认工作范围、允许修改的仓库和验收标准。仓库变更和凭据分别授权。

示例中的标准需要同时包含空字段提示和有效输入提交。完成这一步后，得到一项已确认、开发边界明确的请求。

## 2. 跟进实现

在主导航打开**工作台**（`/automations?tab=board-flow`），选择项目并打开已确认的卡片。启动或恢复开发会话，在卡片上处理提问和审批请求。

根据项目的仓库集成配置，开发泳道会记录 Pull Request 或其他代码引用。打开对应引用查看变更。把澄清结果保留在卡片上，让审阅者能够跟踪同一项工作。

## 3. 验证变更并记录审阅决定

打开卡片中的验证结果。核对代码差异是否符合约定范围，并逐项检查是否满足验收标准。确认测试对应的提交或候选版本，以及测试实际使用的环境。

检查失败时，附上未通过的验收项和证据，退回修复。修复后重新检查新版本。旧提交的报告不能证明当前变更已经通过验证。

当卡片关联了已确认的需求、代码变更、验证证据和审阅决定，你就完成了本教程。后续合并和发布按项目的[审阅与发布流程](/zh-cn/software-factory/review-release/)执行。

如果卡片停止推进，按[受阻卡片排查指南](/zh-cn/getting-started/delivery-board-troubleshooting/)查找原因和下一步。

## 下一步
