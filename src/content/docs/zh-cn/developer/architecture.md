AI Workforce 将产品工作空间、员工执行与结构化工作记录连接起来。同一个员工可以参与交互会话、自动化运行或交付泳道，而每个入口保留各自的任务与执行上下文。

## 产品与执行层

| 层次                   | 职责                                                       |
| ---------------------- | ---------------------------------------------------------- |
| 产品界面               | 工作空间、员工档案、对话、任务收件箱、自动化与交付工作台。 |
| 应用服务               | 协调授权、配置、会话准备、执行和持久化。                   |
| 领域模型               | 定义员工、会话、Issue、Job、触发规则、运行与交付状态。     |
| 基础设施与运行时适配器 | 连接存储、执行内核、MCP 工具、代码平台和外部服务。         |

前端采用 TypeScript React，Python 后端分别组织应用用例、领域规则与基础设施集成。运行时集成提供执行能力，实际可用工具和执行行为取决于配置的运行时与员工实例。

## 从岗位到执行

已发布模板提供初始岗位与能力。创建工作空间员工后得到一个实例，实例完成初始化才能使用。会话承载对话和执行上下文，包括本次执行准备好的能力与已授权资源。

Skill 提供工作方法，Plugin 打包能力，MCP 连接外部工具。这些概念是相互配合的构件，不能互相替代，也不等同于员工本身。

## 工作与编排

收件箱 Issue 记录可行动事项及其来源观察，可以转入工作台草稿，等待需求确认。交付卡片把确认后的需求关联到泳道执行、代码引用、验证与人工介入。某个阶段需要共同处理候选版本时，由批次协调多张卡片。

自动化 Job 保存执行定义。启用自动执行后，触发规则调用已发布 Job。每次调用产生一条运行记录及其结果。复用会话的 Job 可以积累上下文，新会话则隔离每次执行。

## 授权与证据

工作空间访问权限决定成员能查看或操作哪些资源。使用代码仓库凭据时，还会检查执行员工当前的授权。源定义或自然语言约束本身不能授予访问权限。

通过持久化记录追踪实际发生的工作：会话用于检查对话，运行记录用于检查自动化状态，Issue 回执用于确认采集保存，交付记录用于检查代码、测试、合入和发布。这些记录回答不同问题，需要结合判断。
