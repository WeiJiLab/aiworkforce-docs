**AI Workforce 是面向企业的 AI 研发协作与交付平台。** 它把专业数字员工、研发人员、项目知识和工程系统组织在一条从需求、开发、测试、安全到发布的路径上。团队可以和现场交付工程师（FDE）一起定义岗位，用样例验证，再交给项目使用。[从岗位访谈到第一份交付结果](/zh-cn/build/)

平台由专业数字员工、研发协作与交付体系、企业级运行底座组成。AI Workforce 管理会话、工具权限、执行环境、系统集成和交付证据，让团队可以持续改进软件交付方式。[比较企业部署方式](/zh-cn/deployment/managed-agents/)

## 从交付信号到可验证的软件

在下面的交付看板上，跟着 Story #128 看团队如何把「邀请工作空间成员时选择角色」从调研发现推进到测试环境。

![AI Workforce 三列交付看板。竞品调研发现经人工审阅后，以 Story #128 加入 Backlog，后续关联 GitHub Actions 流水线结果。](/illustrations/delivery-board.svg)

1. **收集发现。** 定时调研 Job 从竞品更新日志中发现了邀请时选择角色的功能，将发现和来源一起记录到任务收件箱。[配置定时 Job](/zh-cn/automate/triggers-schedules/)
2. **人工审阅并加入 Backlog。** 团队成员在任务收件箱审阅发现，将它作为 Story #128 转入交付项目。开始开发前，团队在卡片上确认工作范围和验收条件。[审阅需求并确认范围](/zh-cn/user-guide/human-approval/)
3. **验证变更。** 在「交付」页签，PR #62 关联到 GitHub Actions 运行 #482。构建与测试已通过，变更已部署到测试环境，生产发布仍待执行。[接入 CI/CD 流水线](/zh-cn/software-factory/cicd/)
