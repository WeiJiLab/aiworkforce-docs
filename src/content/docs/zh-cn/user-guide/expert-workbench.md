专家工作台适合和数字员工一起完成或审阅一项具体的研发产物。你可以从工作空间的员工会话开始。如果员工插件提供专用界面，也可以在工作空间管理里打开**自定义工作台**。能打开哪些应用，取决于当前工作空间的员工、插件和权限。

| 任务       | 提供给员工的材料             | 要审阅的产物                       |
| ---------- | ---------------------------- | ---------------------------------- |
| 需求与规格 | 原始请求、限制和示例         | 需求范围、待澄清问题和验收标准     |
| 代码审查   | PR 或变更文件、已确认的标准  | 带文件位置的审查发现和修改建议     |
| 用例与验证 | 验收标准、待测版本和测试环境 | 测试用例、实际结果和仍待验证的条目 |

可以在[数据导出权限示例](/zh-cn/getting-started/expert-workbench-example/)里演练这三项工作。

## 从会话或自定义工作台开始

1. **开启会话。** 在工作空间侧栏选择一名职责匹配且已就绪的员工，交代输入、预期产出和验收标准。[交办任务与跟进会话](/zh-cn/user-guide/agent-chat/)。
2. **打开专用界面。** 在目标工作空间进入**自定义工作台**，选择已安装的应用。例如，插件可以在相关员工会话旁边展示仓库文档或报告。[了解 Plugin App 如何提供专用界面](/zh-cn/developer/plugin-apps/)。
3. **审阅结果。** 对照标准核对来源、版本和证据。有遗漏时让员工定向修改，证据充足后记录人工确认。[审阅结果与产物](/zh-cn/user-guide/artifacts-evidence/)。

## 在交付工作台完成交接

一项变更需要多个岗位协作时，把已确认的规格、PR 和测试证据关联到交付卡片。交付工作台用卡片跟踪任务分派、交接和验收。[在已有看板上交付第一条 Issue](/zh-cn/getting-started/quickstart/)。
