专家工作台把已就绪的数字员工和 **Plugin App** 结合在一起。数字员工负责执行任务和访问工具，Plugin App 提供面向任务的工作界面，用来展示规格、浏览仓库文档、审阅报告或执行交互式检查。本页聚焦员工插件提供的应用，以及审查人如何在同一条证据链上作决定。

Plugin App 有两个入口：

| 入口                            | 打开后的行为                                                                               |
| ------------------------------- | ------------------------------------------------------------------------------------------ |
| 工作空间里的**自定义工作台**    | 列出已安装并启用插件、且员工已经就绪的应用。你可以直接打开应用，也可以把它固定到主侧栏。   |
| 员工会话中已完成的 MCP 工具结果 | 在结果旁打开应用，并恢复这次工具调用保存的输入和输出。适合解释或继续某一次具体的工具调用。 |

能看到哪些应用，取决于工作空间里的员工、员工使用的插件版本和你的工作空间权限。

## 先选择任务视图

| 视图                | 交给员工的材料               | 在应用中完成的动作                     |
| ------------------- | ---------------------------- | -------------------------------------- |
| **Security Review** | 权限范围、敏感数据和架构决策 | 筛选风险，打开证据位置，请员工补充证明 |
| **Code Review**     | PR 快照、变更文件和验收标准  | 定位发现，要求修改或接受当前审查       |
| **Test Evidence**   | 测试环境、修订版本和运行记录 | 对照初测与复测，接受证据或继续验证     |

可以在[数据导出权限示例](/zh-cn/getting-started/expert-workbench-example/)里切换三个视图，演练从安全边界到发布决定的完整路径。

## 从工作空间打开应用

1. 打开目标工作空间，在工作空间导航中选择**自定义工作台**。
2. 选择并打开应用，确认顶部显示的员工、仓库、PR 或运行记录符合当前任务。
3. 先选 **Security Review**、**Code Review** 或 **Test Evidence**，再使用筛选、展开和版本切换控件缩小范围。
4. 需要补充证据时，选择**加入员工消息草稿**或**让员工补充证据**。发送前检查草稿中的上下文。
5. 做出决定后，选择**确认审查结果**、**要求修改**或**接受测试证据**。经常使用的工作台可以固定到主侧栏。

应用也可能提供会话报告。提供报告时，核对报告中的运行编号或版本是否对应当前工作。 [提供任务上下文](/zh-cn/user-guide/knowledge-context/)说明了如何把应用需要的文档和限制交给员工。

## 从工具结果打开应用

1. 在员工会话中运行提供应用界面的 MCP 工具。
2. 在已完成的工具结果上选择打开应用的操作。
3. 使用应用前先检查恢复的工具输入和结果。应用从这次保存的调用开始，因此可以核对产生该结果的同一组证据。
4. 使用应用请求后续处理、把上下文加入消息草稿或读取已授权资源。发送前，在会话里检查这份草稿。

有些应用可以请求模型生成文本，也可以请求打开链接或下载文件。控制台会在这些操作前要求确认。具体可用操作取决于应用声明和当前会话。

## 检查权限和就绪状态

满足下面条件时，工作台才会列出应用：员工已经就绪，插件已安装并对该员工启用，并且你的账号有权在该工作空间执行任务。如果空间里没有对应应用，请让工作空间管理者检查员工使用的插件版本和初始化状态。外部连接仍需单独授予。打开 Plugin App 不会自动给员工或外部服务增加凭据。

## 审阅结果并交接

应用是工作的操作界面。员工会话保存对话、工具调用、草稿和执行记录。接受结果前，检查来源、插件或仓库版本、预期结果和证据。安全发现要回到[安全与权限](/zh-cn/deployment/security/)确认授权边界，代码发现要回到[审阅与发布](/zh-cn/software-factory/review-release/)确认阶段，文件和报告则参阅[审阅结果与产物](/zh-cn/user-guide/artifacts-evidence/)。

同一项变更需要多个岗位或分阶段验证时，把已确认的规格、实现引用和测试证据关联到交付卡片。交付工作台负责跟踪不同岗位之间的分派、交接和验收。[在已有看板上交付第一条 Issue](/zh-cn/getting-started/quickstart/)。

要开发这类界面，请参阅[开发 Plugin App](/zh-cn/developer/plugin-apps/)和 [Plugin App API](/zh-cn/developer/plugin-app-api/)。
