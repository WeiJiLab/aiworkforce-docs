员工需要相关上下文才能完成有效工作。AI Workforce 当前提供任务消息与附件、项目文件、空间记忆，以及经过授权的连接。它们是不同的信息来源，不能因为文档可访问，就假定员工已自动阅读全部内容。

## 选择信息存放位置

| 信息                   | 合适位置                     |
| ---------------------- | ---------------------------- |
| 仅适用于本次任务的要求 | 当前会话消息。               |
| 报告、截图或原始文档   | 产品支持的附件或项目文件。   |
| 稳定的团队目标或约定   | 经过审核的空间记忆。         |
| 由其他系统维护的信息   | 通过可用工具访问的授权连接。 |
| 密钥或访问凭据         | 对应的凭据设置。             |

首次尝试时，可以提供一小段原文，并要求员工引用实际使用的段落。基于文件工作时，说明相关文件名与章节。上传文件或列表中出现文件，都不能证明内容已经进入模型上下文。

## 为 Plugin App 准备审查上下文

打开 Security Review 或 Code Review 前，确认工作台显示的员工、仓库、PR 修订版本和架构决策一致。安全审查还需要给出目标资源范围、敏感字段处理方式和拒绝路径。测试证据需要明确测试环境、运行编号和待测修订版本。

工作台中的上下文只会影响当前应用会话。选择**加入员工消息草稿**后，员工要等你发送下一条消息才会收到这些材料。请把长期有效的约束放进经过审核的空间记忆，把单次审查的文件位置和验收标准留在当前会话。

## 维护空间记忆

打开工作空间管理中的**空间记忆**，按内容搜索，或按类型和状态筛选。记忆类型包括目标、约束、偏好、决策、术语和标准。

有管理权限时，可以添加能跨任务使用的简短陈述，并说明范围与适用条件，例如某项命名规范适用于哪个项目。待确认记忆需要作出审核决定：阅读全文，必要时编辑，再确认或拒绝。已确认内容失效后应撤销。

记忆状态为**待确认**、**已确认**、**已拒绝**与**已撤销**。已拒绝和已撤销内容不应作为当前工作依据。更新记忆不会改写过去的回答，也不会撤销已执行的动作。

## 有目的地使用外部知识

连接只会在配置的授权范围内提供外部能力。要求员工读取相关来源，并在结果中附上链接或摘录。自动化依赖该来源前，先通过一次边界明确的读取验证访问。

这一流程不承诺对组织文档进行自动索引、同步或穷尽检索。如果当前实例连接了独立知识服务，应按该服务的配置使用，并检查它返回的证据。

## 排查上下文缺失

检查工作空间、资料位置、记忆状态和员工授权。询问实际使用了哪个来源；补充缺失原文或精确文件引用，再执行与问题相关的最小任务范围。

发出任务后，参阅[查看执行进度](/zh-cn/user-guide/sessions-planning/)。工作空间和连接设置见[工作空间](/zh-cn/user-guide/workspace/)和[MCP 集成](/zh-cn/build/mcp-integration/)。
