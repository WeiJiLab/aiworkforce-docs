产物是员工生成的报告、源文件或关联 Pull Request 等输出。证据则解释为什么可以相信有关工作的判断。接受结果前，应同时检查二者。

## 检查会话输出

打开员工会话，在产物资源区查找生成文件和变更文件。选择文件，打开产品支持的预览或源码视图。会话关联 Pull Request 时，可以通过 PR 入口查看。

文件出现在列表中，表示有一份输出需要审核；这本身不能证明员工使用了正确输入，也不能证明任务已满足验收标准。

## 理解文件变更

执行环境提供所需版本时，变更视图以会话首次执行前的版本作为比较基准。检查实际修改，并核对变更范围是否符合请求。

有些会话缺少可用基准、存在交错修改、文件已还原，或缺少完整结束版本。无法精确比较时，界面会说明原因。此时应阅读文件全文，并取得额外验证，再判断哪些变化可以归因于当前会话。

较大文件或二进制文件可能没有行内差异。内容被截断时，当前显示只是部分结果；需要完整内容时，通过产品提供的项目文件入口打开。

## 按验收标准检查证据

研究与报告任务应核对来源链接和引用原文。软件工作应检查实现、测试结果和相关审核信息，确认哪些检查实际执行过，以及哪些内容仍未验证。

收件箱事项的证据可能包含来源 URL 和摘录。保留对来源的观察，与“问题已经解决”的结论分别判断。

## 排查问题

产物列表读取失败时，使用重新读取操作并查看报错。无法预览时，尝试产品提供的源码或项目文件视图。缺少证据时，要求员工补充具体来源或验证结果，再判断是否完成。
