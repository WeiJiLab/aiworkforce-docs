Agent 对话用于向员工交付工作，并讨论执行结果。会话将交流与相关工作组织在一起，方便你持续完善同一任务，无需每次重新说明所有决定。

## 开启有效会话

在正确工作空间中选择已就绪的员工。目标应符合员工职责，在请求中同时提供输入、期望输出、约束和验收标准。

例如，要求基于给定原文整理摘要、列出待确认问题，或提出实现方案。说明员工应该只调查，还是允许修改文件。要求执行某项操作，不会自动授予缺失的连接权限。

## 保持上下文聚焦

纠正遗漏或澄清当前任务时，继续使用原会话。指出需要修改的具体要求，并说明下一次结果如何验收。

目标或工作背景发生明显变化时，开启新会话。多个无关项目混在一次对话中，会增加审核难度，尤其是会话还关联文件和执行记录时。

## 执行中与执行后检查

阅读员工进度和最终回答。产生文件后，在产物区域打开查看。涉及代码工作时，检查变更文件与验证证据，再判断需求是否完成。

要求员工区分已执行动作和建议的后续步骤。“应该运行测试”与已经记录的测试结果不同；Pull Request 链接也应打开检查，不能只依赖对话中的描述。

## 处理不完整结果

缺少输入时，在会话中补充材料。连接不可用时，请空间创建者、团队 leader 或管理员核对授权。见[团队与访问权限](/zh-cn/administration/teams-access/)。执行失败时，先阅读可见错误再决定是否重试；重复发送指令不会修复不可用的执行环境。

一次有效协作应当留下符合验收标准的结果、可检查的支持证据，以及由人作出的后续行动决定。

继续阅读[产物与证据](/zh-cn/user-guide/artifacts-evidence/)和[任务收件箱](/zh-cn/user-guide/inbox-tasks/)。
