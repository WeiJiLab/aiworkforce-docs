在专家工作台，你可以和数字员工一起澄清需求、审查代码或验证测试结果。在工作空间侧栏选择一名已就绪的数字员工，打开会话，说明预期产出和验收标准。如果空间里还没有合适的员工，先[创建数字员工](/zh-cn/getting-started/first-employee/)。

在[专家工作台示例](/zh-cn/getting-started/expert-workbench-example/)中，沿着一条数据导出需求，查看规格、PR 审查和测试用例，最后判断现有证据能支持哪项发布决定。

## 从工作台动作继续会话

工作台中的**加入员工消息草稿**会把当前发现、文件位置和关联标准带回会话。**让员工补充证据**适合权限边界、失败路径或测试覆盖仍不清楚的情况。发送前检查草稿是否包含正确的仓库、修订版本和审查范围。

**要求修改并回到员工**适用于 Code Review 已经定位到文件和验收标准的场景。员工返回新修订后，在同一个会话里重新打开工作台，核对新的 PR 快照和测试运行记录。

## 开启有效会话

选择符合员工职责的目标，在同一条请求里写清期望输出、限制和验收标准。附上任务需要的资料，或指出它们的位置。见[提供任务上下文](/zh-cn/user-guide/knowledge-context/)。

例如，要求基于给定原文整理摘要、列出待确认问题，或提出实现方案。说明员工应该只调查，还是允许修改文件。要求执行某项操作，不会自动授予缺失的连接权限。

发送前检查会话的[权限模式](/zh-cn/user-guide/sessions-planning/#选择执行边界)。

## 保持上下文聚焦

纠正遗漏或澄清当前任务时，继续使用原会话。指出需要修改的具体要求，并说明下一次结果如何验收。通过员工的历史会话返回之前的工作，可以置顶需要经常查看的会话。

目标或工作背景发生明显变化时，开启新会话。多个无关项目混在一次对话中，会增加审核难度，尤其是会话还关联文件和执行记录时。

## 执行中与执行后检查

发出任务后，关注会话状态和工具活动。员工返回结果后，对照原始要求检查。见[查看执行进度](/zh-cn/user-guide/sessions-planning/)和[审阅结果与产物](/zh-cn/user-guide/artifacts-evidence/)。

## 处理不完整结果

缺少输入时，在会话中补充材料。连接不可用时，请空间创建者、团队 leader 或管理员核对授权。见[团队与访问权限](/zh-cn/administration/teams-access/)。执行失败时，先阅读可见错误再决定是否重试；重复发送指令不会修复不可用的执行环境。
