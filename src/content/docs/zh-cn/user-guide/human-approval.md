人工确认是一项决定，不是一枚状态徽章。当请求会改变范围、执行需要人才能继续，或结果将被当成已接受时，AI Workforce 需要这个决定。使用员工并不包括编辑员工包。本页讲的是你面前的这些决定。

## 人在哪里做决定

| 时刻         | 你确认什么                 | 确认不会做什么           |
| ------------ | -------------------------- | ------------------------ |
| 收件箱审阅   | 事项真实，并且值得下一步   | 开始写代码或批准仓库     |
| 工作台草稿   | 范围、验收标准和允许的仓库 | 补上缺失凭据或修好流水线 |
| 会话中的提问 | 员工提出的一个澄清         | 悄悄放宽任务             |
| 接管         | 下一步由你自己来做         | 在恢复暂停时自行清除     |
| 审阅         | 产物或变更符合你写下的标准 | 证明没跑的测试已经通过   |

收集到的收件箱事项不是批准。流畅的回答不是批准。接受结果意味着你能指出输出和证据。如何阅读输出，见[产物与证据](/zh-cn/user-guide/artifacts-evidence/)。

## 接管并交还

在交付卡片上，接管会停止自动推进并保留当前状态。记下你改了什么。泳道应继续时，通过恢复操作交还工作。只恢复暂停并不能清除接管。结束对 Pull Request 的跟进也不会关闭外部 Pull Request。

对于自动化，手动运行一个已暂停的 Job 不会重新启用它的触发规则。如果运行在等人，先作出该决定再重试。见[批准与通知](/zh-cn/automate/approvals/)。

## 把决定写具体

写明决定、范围和证据。“只批准前端仓库上已写明的需求”是一项决定。“看起来不错”不是。如果豁免某项检查，写明检查项、原因、范围和剩余风险。
