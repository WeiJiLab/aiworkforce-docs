批准是记录下来的人工决定。可从顶栏铃铛或收件箱的**通知**页签查看通知，再打开关联事项或卡片作出决定。支持相应触发类型时，也可以用 IM 启动 Job。

## 要求的是决定，不是状态

当自动化否则就会放宽范围、写入外部系统，或把收集到的请求当成可以开发时，使用批准。今天存在的模式是：

- 收集到的 Issue 留在收件箱，或成为工作台草稿。是否需要人工确认由目标看板的[接入规则](/zh-cn/software-factory/intake/)决定。
- 读取 Run 需要读取权限。取消需要取消权限，并发出停止请求。通过结果和会话确认执行是否已停止。符合条件的 Run 可从运行历史重试。
- 交付卡片可以提问、记录接管，并要求明确交还。

[人工确认](/zh-cn/user-guide/human-approval/)是这些决定面向使用者的一面。本页是自动化这一面。

## 不要把一条消息当成许可

IM 触发可以启动 Job。消息是输入。它不是合并、部署或超出员工授权去花费的授权。如果 Job 输出草稿，请检查目标看板的接入和审批规则。如果需要团队看到失败，把他们指到运行记录和会话。除非该目的地已经配置，并且你见过它收到过一次，否则不要假设未读聊天发出了页面、邮件或工单。

把决定写成范围加上证据。豁免的检查要写明检查项、原因和风险。重试被允许重复什么，见[运行与恢复](/zh-cn/automate/runs-recovery/)。
