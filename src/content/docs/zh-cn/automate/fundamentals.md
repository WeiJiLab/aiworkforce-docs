自动化启动工作并记录发生了什么。它不只是定时任务。在相应类型可用时，Job 可以由日程、Webhook、平台事件、Issue 或 IM 消息调用，也可以手动运行。下面把 Job、触发规则和运行分开，这样失败才有地方可查。

事件驱动的启动见[事件驱动自动化](/zh-cn/automate/event-driven/)。入站 Webhook 见[监视与 Webhook](/zh-cn/automate/watchers-webhooks/)。重复工作见[循环与周期性工作](/zh-cn/automate/loops/)。人介入的步骤见[批准与通知](/zh-cn/automate/approvals/)。

自动化 **Job** 定义要做的工作，以及负责执行的员工或受支持执行器。**触发规则（Trigger）**定义何时调用该 Job。**运行（Run）**记录一次执行。区分这些概念，才能在调整调度时保留任务身份，并准确定位失败。

## 创建有边界的 Job

在 `/automations` 打开「自动化」，选择你有执行权限的工作空间及员工。明确任务、输入与可检查的输出，先从可以人工核验的小任务开始。

启用触发规则前，先约定哪些工作由员工按规则处理，哪些决定由人负责。写清员工可以使用的工具和数据源、审阅时需要的证据，以及无法在约定范围内完成时应报告哪些信息。参考[批准与通知](/zh-cn/automate/approvals/)安排人工处理异常的方式。

决定每次运行使用新会话，还是复用 Job 绑定的会话。新会话隔离每次运行，复用会话则积累上下文。协作成员手动执行复用会话的 Job 时，仍使用 Job 原本绑定的会话。

## 保存、执行、发布、启用

这些操作的效果不同：

| 操作         | 效果                               |
| ------------ | ---------------------------------- |
| 保存草稿     | 保存配置，继续编辑。               |
| 手动执行     | 立即创建一次可以检查的运行。       |
| 发布         | 发布执行配置，不会创建运行。       |
| 启用自动执行 | 允许已配置的自动触发规则调用 Job。 |

发布不要求测试成功。建议先执行并检查结果，再启用周期触发。暂停的已发布 Job 仍然可以手动执行；手动执行不会恢复自动触发。

## 添加触发规则与结果去向

平台提供定时、Webhook、平台事件、Issue 和 IM 等触发类型，具体以当前页面可选项为准。一个 Job 可以有多条调度规则，每条规则属于一个 Job。除 Job 状态外，还应检查规则的输入与启用状态。

对于采集可行动事项的任务，添加「收集任务 / Issues」，选择工作空间收件箱或工作台项目。该工具不是所有 Job 的必填项。配置后，成功采集需要服务端回执，仅在会话中总结不代表已保存 Issue。没有符合条件的事项时，也需要记录空采集结果。当前采集界面要求使用 Claude Code 执行内核。

### 示例：定期收集缺陷报告

设置一个 Job，每个工作日查看已授权来源中的新增缺陷报告。让员工记录来源链接、观察到的现象、已有复现步骤，以及还缺哪些信息，并将待处理事项送入工作空间收件箱。检查首次运行时，对照原始报告和采集回执。由分流负责人决定哪些事项需要补充信息，哪些可以转成交付草稿。转交后的流程见[从 Issue 到 PR](/zh-cn/recipes/issue-to-pr/)。

## 检查与恢复

打开运行历史，检查状态、输出、会话及采集回执。失败时，先解决授权缺失、输入不合法或工具不可用等原因，再重试。采集任务应使用稳定的来源标识，避免重复事项。进入工作台的草稿仍需人工确认，才会开始开发。
