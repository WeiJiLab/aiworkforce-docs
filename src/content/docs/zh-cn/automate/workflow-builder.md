当前产品里有两种定义工作流的方式。**Job** 是一个执行器加上它的触发规则。**编排**把交付看板某条泳道上的两个或更多执行器串起来。没有第三块画布，用来描述不挂在泳道上的任意流程。[自定义工作流](/zh-cn/workflows/custom-workflows/)写的是同一条边界。

## 组合一个 Job

打开 **Automations**（`/automations`）。

1. 选择执行员工，并写清任务、输入和输出。
2. 选择每次运行新建会话，或复用 Job 绑定的会话。复用会积累上下文。新建会话让各次运行更容易比较。
3. 保存，手动运行，并在发布之前阅读这次运行。
4. 添加一条或多条触发规则。每条调度规则都属于这个 Job。事件和 Webhook 是不同的类型。见[事件驱动自动化](/zh-cn/automate/event-driven/)。
5. 如果 Job 要把请求登记下来，添加**收集任务 / 事项**，并选择工作空间收件箱或工作台项目。这个工具是可选的，收集界面要求 Claude Code 运行时。

发布保存配置。它不创建运行。只有手动结果可以接受时才启用自动执行。Job 编辑器不保存分支、扇出或重试次数。重复工作使用日程规则，见[循环与周期性工作](/zh-cn/automate/loops/)。

## 组合一条泳道编排

从自动化页面打开**编排**。选择工作空间、看板和泳道。列表显示该泳道的执行器：Agent 任务和允许列表中的代码执行器。

1. 创建编排并至少添加两个节点。一个节点不能作为编排启用。把这种日程配置在 Job 上。
2. 连接节点。连线可以在成功、失败或无论成败时继续。失败用于兜底，不用于主路径。
3. 把每个下游输入映射到触发或上游输出。必填字段必须映射。编辑器会报告契约错误；上游契约变化时，编排可以暂停。
4. 保存，然后启用。添加一次手动运行或一条 Cron。Webhook、GitHub、Issue 和 IM 触发留在 Job 上。未启用的编排在 Cron 到点时不会启动。
5. 打开编排运行。每个节点是等待、已排队、成功、失败或跳过。

节点可以对列表扇出，并在运行失败后重试。图会拒绝环，所以没有循环计数器。多步骤的工程交付仍然属于[软件工厂](/zh-cn/software-factory/overview/)看板。编排用来规定一条泳道上执行器的顺序。它不代替卡片确认。

## 仍然不能画出来的部分

过程中的人使用[批准与通知](/zh-cn/automate/approvals/)或交付卡片上的接管。技能可以在 Agent 包里声明条件、分支、并行步骤和人工确认。这些步骤要在运行轨迹里确认。写在正文里并不会创建它们。见 [Agent 组合](/zh-cn/build/composition/)。
