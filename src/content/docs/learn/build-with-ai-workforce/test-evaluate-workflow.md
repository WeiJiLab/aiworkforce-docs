Check the package structure first, then check its behavior on tasks. [Employee testing](/build/testing/) covers validation and trials for normal input, missing input, and out-of-scope requests. Keep the inputs, template version, and accepted results so the next version can be compared.

For a delivered software change, separately compare the tested revision and results with the card's acceptance criteria. [Execution evaluation](/software-factory/evaluation/) and [Evaluation governance](/operate/evaluation-governance/) explain those records and decisions. A structurally valid package does not prove a particular change passed, and these steps do not imply an automatic benchmark suite.
