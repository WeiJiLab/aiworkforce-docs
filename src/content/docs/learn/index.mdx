## Apply the method to real work

A good instruction connects the desired outcome to the information and boundaries needed to reach it. Keep lasting rules distinct from the current request, and use the same acceptance criteria when reviewing the result. The guides below put those methods into a complete workflow.

<PortalLanding portal="learn" section="guides" />

## Check that the work is ready to hand off

Before confirming a task, make sure the team can answer these questions:

- **Outcome:** Who needs the change, what should improve, and who can resolve questions?
- **Scope:** Which resources and changes are allowed, and which work belongs in a later task?
- **Acceptance:** What observable behavior would let another person accept or reject the result?
- **Evidence and decisions:** Which outputs and checks should be reviewed, and where is human confirmation required?

When an answer is missing, turn it into a specific question. When the answer changes the agreed scope, update the requirement and its criteria before continuing execution. Use [feedback and review](/learn/feedback-review/) to decide whether a finding is a defect, a new requirement, or a request for explanation.
