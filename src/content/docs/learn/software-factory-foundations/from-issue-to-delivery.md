An incoming Issue records a request. A delivery card connects confirmed work to implementation and verification. The confirmation between them is a decision about scope and acceptance criteria.

## Follow one request

1. Review the form-validation Issue in the inbox and route it to the intended delivery project.
2. On the draft card, confirm the message to change, permitted repositories, and checks for empty and valid input.
3. Follow the linked development session and inspect the code reference it produces.
4. Compare checks on the candidate revision with both criteria, then record acceptance or return the work with the failed criterion.

The Issue's arrival starts intake; the confirmed card authorizes the agreed implementation scope. Merge and release remain later steps in the configured project process.

## Try this judgment

An imported Issue asks for a “better form.” Can development proceed immediately?

First clarify the behavior and acceptance criteria on the draft. A source request alone does not resolve that ambiguity.
