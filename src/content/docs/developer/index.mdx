## Assemble the building blocks

An employee role defines the job. Skills provide working methods, plugins package capabilities, and MCP connects tools. Platform APIs expose implemented resource operations. Choose the pieces your workflow needs and verify the access available to the execution employee.

<PortalLanding portal="developers" section="guides" />

## Verify one complete workflow

1. Agree on the intended outcome, allowed inputs and resources, and acceptance criteria. Use [Learn](/learn/) to resolve gaps in the work definition.
2. Implement the smallest useful package or integration. Check its supported fields and calls, entry points, and authorization requirements.
3. Try a normal request, missing inputs, and a denied or unavailable resource. Inspect the execution records and output evidence, including how the workflow recovers.
4. Validate the employee package where applicable, then try the capability through a workspace employee with the intended runtime and access.

Before deploying or broadening access, review [deployment and security](/deployment/security/). Use the [contribution guide](/developer/contributing/) for source changes and documentation updates.
